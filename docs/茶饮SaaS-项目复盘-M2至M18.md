## 三、质量战果：抓出的真缺陷（复盘核心资产）

| # | 缺陷 | 发现方式 | 根因层级 | 危害 |
|---|---|---|---|---|
| 1 | 支付回调无租户上下文，`tenant_id=0` 查不到流水必挂 | Review 方案 + 冒烟 | 框架/多租户 | **资金链路阻断**（M5 R1 修复） |
| 2 | SaInterceptor 自定义 auth 替换默认登录校验，B 端接口曾可未登录访问 | 冒烟 | 框架/安全 | **越权裸奔**（M9 bdf1bdd） |
| 3 | 钱包并发开卡：RR 旧快照看不到并发方刚提交的行 → NPE 静默失败 | 并发集成测试 | 数据库隔离级别 | 资金静默丢失（M12） |
| 4 | 积分扣减锁在一致性读之后：并发双单可双双通过刷负 SUM | 并发集成测试 | 并发时序 | 资产刷负（M12） |
| 5 | mini-program mockCallback 走 Result 解包，但回调回纯文本 SUCCESS → 轮询永不启动 | 运行时冒烟 | 前后端契约 | 支付流程卡死（M15） |
| 6 | `LocalDateTime.now()` 带纳秒写 `valid_start`，MySQL datetime(0) 四舍五入入到下一秒 → 同秒用券误判"不在有效期" | M18 复跑 FAIL，三角定位（时序复刻探针 + DB 时间线 + CAST 实测） | 数据精度边界 | **间歇性极强**，两轮全绿后才暴露 |

另有权限种子三轮收敛中修掉的越权按钮（R4 库存越权、R8 退款/取消越权）——属配置缺陷而非代码缺陷。

**规律提炼**：
- 6 个真 bug 中 4 个（#1/#2/#3/#4）是**框架层与并发层**问题，业务 CRUD 反而零缺陷——质量投入应继续压在框架边界与资金并发上。
- #5/#6 都是**"只验证编译/构建，未做运行时点穿"**漏掉的——M18 套件落地后此类问题已有统一回归入口。
- #6 这类间歇性缺陷（时间边界、小数舍入）只能靠**可复跑的自动化冒烟**抓，人工点测基本无解。

## 四、做得好的（可复用经验）

1. **契约先行 + 编号贯穿**：接口需求文档 F-XXX 编号写进每个 commit message，102 个 commit 无一游离于契约外；文档随代码同步升版（v1.0→v1.4），前后端从未各说各话。
2. **红线硬门禁**：8 条编码红线 + 多租户红线进 pre-commit hook（@Autowired/System.out/事务/金额类型/SELECT * 自动拦截），配合每次任务后的红线审查清单，102 commits 零红线违规记录。
3. **幂等与一致性的统一武器库**：`bizNo+bizType` 唯一键 DB 兜底、条件更新防并发（`status=from`、`balance>=amount`）、FOR UPDATE 悲观锁、afterCommit 再推 WS——同一套模式贯穿库存/积分/钱包/券/回调五条资金线。
4. **差值断言的冒烟哲学**（M18）：不硬编码演示库状态，全部前后差值断言 + 自建可回收数据（smoke-r8 账号、临时券模板），套件可无限复跑——直接教训来自 M15 一次性脚本"跑一次即废"。
5. **HANDOFF + 会话记忆机制**：每个里程碑写状态快照，AI 协作跨会话零上下文丢失；"接手者须知"沉淀了 11 条关键实现事实（@MapperScan、SaInterceptor 陷阱、EP 变量覆盖层级等），同类坑没有踩第二次。
6. **Owner 决策显式化**：P0-4 储值即时支付、退款券不退、store-terminal 方案 A（不建独立端）、wx-login 一期 mock——全部有拍板记录，避免开发侧自嗨。

## 五、待改进的（教训）

1. **权限种子对齐花了三轮**（M8 两轮 + M12 回归）：PRD 5.2/5.3 权限矩阵与种子 SQL 的对照验证应尽早自动化（种子→矩阵双向 diff 脚本），而不是靠人工比对 + 冒烟抽查。
2. **前后端字段名漂移**：scope/products、salePrice/price、orderId/orderNo 三处字段名不一致均在冒烟期才暴露——types/*.ts 若能从后端 VO 生成（或至少契约表加字段级对齐检查）可提前消掉。
3. **前端"build 通过"≠"运行可用"**：M14 只验证构建，M15 冒烟即穿（mockCallback 缺陷）；组件不渲染（easycom 规则）也是 build 不报错的坑。M18 Playwright S9 只覆盖一条主干流，后续新页面应随做随补 E2E。
4. **无 CI**：冒烟套件、并发测试、pre-commit 门禁都齐了，但全靠手动触发。仓库接入 CI 后，"复跑 9/9 全绿"才能从一次性战果变成常态保障。
5. **时间/精度边界类测试盲区**：datetime(0) 舍入 bug 提示——凡 Java 时间戳直接入库的字段，入库前应统一截断到秒（可做成 BaseEntity/工具方法级约定），而不是等冒烟抓。
