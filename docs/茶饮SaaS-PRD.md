## 2. 产品概述

### 2.1 产品定位

为茶饮连锁品牌总部提供"产品研发 → 供应链 → 加盟商管理 → 点单收银 → 会员营销 → 经营报表"一体化 SaaS。核心差异化：**BOM 配方驱动的实时库存**与**总部-加盟商两级经营体系**。

### 2.2 三端产品

| 端 | 使用者 | 形态 | 说明 |
|---|---|---|---|
| 管理后台 | 平台管理员、总部、加盟商、店长/店员 | Web（Vue3） | 按角色渲染不同菜单 |
| 门店端 | 店长/店员 | Web/平板（可复用后台） | 接单、制作、核销、日结 |
| 顾客端 | 顾客 | 微信小程序 | 点单、支付、会员 |

### 2.3 范围

本期（MVP）范围以规划书 v1.1 第 4.1 节为准；本文档细化其功能需求与权限。

## 3. 角色定义

### 3.1 B 端角色（管理后台/门店端）

| 角色编码 | 角色 | 所属层级 | 一句话职责 |
|---|---|---|---|
| R1 | 平台管理员 | 平台（超级租户） | 品牌入驻、套餐计费、全局配置、平台看板 |
| R2 | 总部管理员（品牌老板） | 品牌总部 | 品牌内最高权限，管全局（默认拥有 R3–R5 全部能力） |
| R3 | 总部-产品研发 | 品牌总部 | 原料档案、配方 BOM、商品发布 |
| R4 | 总部-供应链 | 品牌总部 | 供应商、原料集采、分级价格、采购单处理 |
| R5 | 总部-运营 | 品牌总部 | 加盟商管理、等级评定、营销活动、报表 |
| R6 | 加盟商老板 | 加盟商 | 上架商品、门店库存、采购、接单、本店报表 |
| R7 | 店长 | 门店 | 本店订单、库存、员工管理、日结 |
| R8 | 店员 | 门店 | 接单、制作、核销（无管理权限） |

> 说明：总部管理员(R2) = R3+R4+R5 能力集合；小型品牌初期可只开通 R2。角色-菜单权限由 tea-system 模块配置化，不硬编码。

### 3.2 C 端角色（小程序）

| 角色 | 说明 |
|---|---|
| 顾客 | 游客可浏览门店/商品；下单需微信授权登录成为会员 |

## 4. 功能需求（按模块）

> 格式：功能编号 + 用户故事（As a… / I want… / So that…）+ 验收标准（AC）。
> 模块编号与规划书 5.3 模块划分对应。

### 4.1 租户与权限（tea-system）

**F-SYS-01 品牌开通**
- 用户故事：作为平台管理员，我希望创建品牌租户并分配套餐，以便品牌独立运营。
- AC：创建品牌时生成唯一租户标识；品牌内所有数据带 tenant_id；套餐限制门店数/功能开关。
- **套餐三档（P1-4 决策）**：基础版 99 元/店/月（门店数上限 + 基础功能）/ 专业版 199 元/店/月（+ 营销/报表深度）/ 旗舰版 299 元/店/月（+ 高级数据服务）；套餐=门店数上限+功能开关，配置化（`sys_package` 表）。

**F-SYS-02 用户与角色管理**
- 用户故事：作为总部管理员，我希望创建员工账号并分配角色，以便控制谁能做什么。
- AC：支持按品牌/加盟商/门店层级创建用户；角色可配置菜单与按钮权限；员工可绑定多个门店（如一人管多店）。

**F-SYS-03 登录认证**
- 用户故事：作为 B 端用户，我希望安全登录并自动带出我的数据范围。
- AC：账号密码 + 验证码登录；Sa-Token 会话；登录后按角色返回菜单树与按钮权限集合；支持退出登录与会话过期。

**F-SYS-04 操作日志**
- 用户故事：作为总部管理员，我希望查看关键操作日志，以便追溯问题。
- AC：记录登录、下单、采购、价格修改、配方修改等关键操作；按时间/操作人/门店筛选。

### 4.2 产品研发 - 配方 BOM（tea-bom）

**F-BOM-01 原料档案**
- 用户故事：作为总部产品研发，我希望维护原料档案（名称/单位/规格/分类），以便配方引用。
- AC：原料唯一编码；单位统一（g/kg/个/杯）；可设置库存预警阈值。

**F-BOM-02 配方 BOM 管理**
- 用户故事：作为总部产品研发，我希望为每个饮品定义配方（原料 × 用量），以便门店按标准制作并精确扣库存。
- AC：一个商品对应一个配方；配方行 = 原料 + 用量；支持新增/停用/复制；配方修改需留痕（版本记录）。

**F-BOM-03 毛利试算**
- 用户故事：作为总部产品研发，我希望按原料成本试算商品毛利，以便定价不亏本。
- AC：输入原料成本（或引用采购价）自动计算单杯成本与毛利；成本不可见时给出提示。

### 4.3 供应链（tea-supply）

**F-SUP-01 供应商管理**
- 用户故事：作为总部供应链，我希望维护供应商档案，以便集采询价。
- AC：供应商 CRUD；关联可供应原料；记录联系人/账期。

**F-SUP-02 分级价格表**
- 用户故事：作为总部供应链，我希望按加盟商等级给原料定不同价格，以便激励优质加盟商。
- AC：价格维度 = 原料 × 加盟商等级；等级 A/B/C 可配不同单价；采购单自动取对应等级价格。

**F-SUP-03 采购单（加盟商 → 总部）**
- 用户故事：作为加盟商，我希望按需向总部提交原料采购单，以便门店补货。
- AC：加盟商从门店库存低预警/原料列表选品下单；总部确认单价与发货；状态机：待确认 → 已确认 → 已发货 → 已入库；采购单号唯一。
- **采购权归属（P1-1 决策）**：采购单**仅加盟商（R6）发起**，店长（R7）只负责收货入库，无发起权。
- **集采模式（P0-2 决策 A）**：总部不建中心仓、不做库存；供应商直发门店。总部职责 = 维护供应商 + 分级价格 + 确认采购单（含发货方式：总部发货或供应商直发，可选记录）。

**F-SUP-04 采购入库**
- 用户故事：作为加盟商/店长，我希望确认收货入库，以便库存增加、商品恢复可售。
- AC：入库后门店原料库存按数量增加；入库留痕（操作人/时间/来源单号）。
### 4.4 加盟商管理（tea-franchise）

**F-FRA-01 加盟商档案**
- 用户故事：作为总部运营，我希望管理加盟商档案与等级，以便统一评定与差异化政策。
- AC：加盟商 CRUD；绑定 1 个或多个门店；等级字段（A/B/C，一期人工评定）；加盟商账号开通。

**F-FRA-02 门店档案**
- 用户故事：作为总部运营，我希望维护门店档案（加盟/直营、地址、营业状态），以便全局管理。
- AC：门店归属加盟商或总部（直营）；营业状态影响顾客端可下单；门店有独立库存账。

### 4.5 商品与上架（tea-product）

**F-PRD-01 产品库与商品发布**
- 用户故事：作为总部产品研发，我希望把"配方+规格+定价"组装成商品发布到产品库，以便加盟商选用。
- AC：商品 = 分类 + 名称 + 配方（引用 BOM）+ 规格（去冰/半糖等）+ 建议售价；发布后进入产品库。

**F-PRD-02 加盟商上架**
- 用户故事：作为加盟商，我希望从总部产品库选择商品上架到我的门店，以便顾客下单。
- AC：上架商品引用总部商品定义（配方自动关联）；可调整本店售价（上限可配置）；下架即时生效。

**F-PRD-03 可售状态自动联动**
- 用户故事：作为顾客，我希望只看到门店有库存的商品，以便不买到做不出来的饮品。
- AC：商品可售 = 门店各原料库存 ≥ 配方用量；库存变化实时刷新可售状态；顾客端不展示无库存商品。

### 4.6 门店库存（tea-inventory）

**F-INV-01 库存台账**
- 用户故事：作为店长/加盟商，我希望查看门店原料库存明细，以便掌握补货需求。
- AC：按原料展示当前库存/预警阈值/最近变动；支持手动盘点修正（留痕）。

**F-INV-02 BOM 扣减**
- 用户故事：作为系统，我希望在下单时按配方精确扣减原料库存，以便库存与销售一致。
- AC：见规划书第 6 章；扣减原子性、禁止负库存、超时回补。

**F-INV-03 库存预警**
- 用户故事：作为加盟商，我希望库存低于阈值时收到提醒，以便及时补货。
- AC：低库存列表页 + 后台角标提醒（一期不做推送）。

### 4.7 订单（tea-order）

**F-ORD-01 顾客下单**
- 用户故事：作为顾客，我希望在小程序选门店、加购、下单，以便到店取餐。
- AC：按门店过滤可售商品；提交订单时服务端二次校验库存；生成取餐码。

**F-ORD-02 订单状态机**
- 用户故事：作为门店/顾客，我希望订单状态清晰流转，以便各环节协同。
- AC：待支付 → 已支付 → 制作中 → 待取餐 → 已完成；可取消（超时未付自动取消并回补库存）；可退款（退款后回补库存）。
- **超时取消（P1-5 决策）**：待支付订单 **15 分钟**未支付自动取消并回补库存；超时时长写入配置项（`order.pay-timeout-minutes`），可调。

**F-ORD-03 门店接单**
- 用户故事：作为店员，我希望接单并标记制作/完成，以便流水线作业。
- AC：新订单实时提醒；接单/完成操作留痕；按状态筛选订单列表。
- **实时提醒（P1-2 决策）**：门店端使用 **WebSocket** 实时推送新订单/状态变更（teaser：连接管理见 tea-framework）；一期不做离线推送。

**F-ORD-04 门店手工收银（简版 POS，P0-1 决策）**
- 用户故事：作为店员，我希望在门店端手工创建订单并收款，以便服务到店现金/扫码付款的顾客。
- AC：店员选择本店已上架商品 + 规格 → 生成订单（`order_source = 门店收银`）→ 收款（**现金 / 微信收款码(Native) / 储值**，三选一，不与线上单混淆）→ 入账；受库存联动约束（可售校验同 F-ORD-01）；收款流水计入门店日结。
- **一期边界**：不支持挂单、不开小票、不做多支付方式混合；顾客无需登录。

### 4.8 支付（tea-payment）

**F-PAY-01 微信支付**
- 用户故事：作为顾客，我希望微信支付下单，以便快速完成购买。
- AC：微信支付 V3；金额以"分"存储；支付回调验签 + 幂等。
- **回调可靠性（P1-3 决策）**：回调先落**本地表**（`pay_callback_task`），由 tea-job 定时任务重试处理，不引入 MQ（单体一期）。
- **门店收款码**：门店端手工收银的微信收款走微信 Native 收款码（F-ORD-04 关联）。

**F-PAY-02 退款**
- 用户故事：作为店长/总部，我希望对订单退款，以便处理售后。
- AC：仅已支付订单可退；退款走微信原路退回；退款成功回补库存。
- **退款规则（P0-5 决策）**：
  - 一期**仅支持整单退款**，不支持部分退款
  - 退款顺序：储值支付部分 → 先退回储值账户；微信支付部分 → 原路退回
  - **已核销的优惠券不退还**；使用的积分按规则退还（一期：全额退还）
  - 退款成功后回补原料库存；退款留痕（F-SYS-04）

**F-PAY-03 对账**
- 用户故事：作为总部财务，我希望核对支付流水，以便日结对账。
- AC：日终对账脚本；差异订单标红提示（一期人工处理）。

### 4.9 会员（tea-member）

**F-MEM-01 会员注册与档案**
- 用户故事：作为顾客，我希望微信登录即成为会员，以便享受权益。
- AC：微信授权自动建档；会员归属品牌（跨门店通用）；手机号可选绑定。

**F-MEM-02 积分**
- 用户故事：作为顾客，我希望消费得积分、积分抵现，以便获得复购动力。
- AC：积分规则（消费 1 元 = 1 分，可配置）；积分流水可查；抵现比例可配置。

**F-MEM-03 储值**
- 用户故事：作为顾客，我希望充值储值账户，以便便捷支付。
- AC：充值赠送比例可配置；储值可支付订单；余额流水可查（一期小程序端可做）。
- **储值支付通道（P0-4 决策）**：储值作为独立支付通道（`pay_channel = 储值`）；一期**不支持与微信混合支付**（储值余额不足以支付整单时，不允许使用储值通道）；退款时储值部分退回储值账户。

### 4.10 营销（tea-marketing）

**F-MKT-01 优惠券**
- 用户故事：作为总部运营/加盟商，我希望发优惠券，以便提升复购。
- AC：券模板（满减/折扣）+ 发放范围（全场/指定商品）+ 有效期；顾客端领券/核销；核销联动订单金额计算。

### 4.11 报表（tea-report）

**F-RPT-01 门店经营日报/周报**
- 用户故事：作为店长/加盟商，我希望看本店营业额、订单量、杯量，以便经营调整。
- AC：按日/周/月聚合；数据来自订单流水；加盟商仅看名下门店。

**F-RPT-02 品牌汇总看板**
- 用户故事：作为总部，我希望看全品牌经营与库存汇总，以便决策。
- AC：总营业额/订单量/热销商品 TOP10/门店排行；各门店库存总览（低库存门店突出）。

**F-RPT-03 原料消耗分析（二期）**
- 用户故事：作为总部供应链，我希望看原料消耗趋势，以便集采计划。（二期）

### 4.12 顾客端小程序（C 端）

**F-APP-01 选择最近门店**
- 用户故事：作为顾客，我希望自动定位并选择最近门店，以便就近购买。
- AC：微信定位授权；按距离排序展示营业中门店；可手动切换门店。

**F-APP-02 浏览与下单**
- 用户故事：作为顾客，我希望浏览有库存商品并下单，以便买到能做的饮品。
- AC：商品列表仅展示可售商品（服务端过滤）；规格选择 → 购物车 → 结算 → 微信支付。

**F-APP-03 历史购买记录**
- 用户故事：作为顾客，我希望查看历史订单，以便复购与售后。
- AC：订单列表/详情；状态展示；可再次购买（一键加购）。

## 5. 角色职责权限矩阵

### 5.1 权限模型说明

- 采用 **RBAC**：用户 → 角色 → 菜单/按钮权限；角色可配置，默认提供 R1–R8 预置角色。
- **两级权限**：菜单权限（能不能进这个页面）+ 按钮权限（页面上能不能点这个操作）。
- **数据权限**（谁能看到哪些数据）单独规则，见 5.4。

### 5.4 数据权限规则表

| 角色 | 数据范围 | 规则 |
|---|---|---|
| R1 平台管理员 | 全部品牌 | tenant_id 为空（超级租户）或全量 |
| R2–R5 总部角色 | 本品牌全部门店 | tenant_id = 本品牌 |
| R6 加盟商 | 名下门店 | tenant_id = 品牌 且 store_id ∈ 名下门店 |
| R7 店长 | 本店 | store_id = 本店 |
| R8 店员 | 本店（只读部分） | store_id = 本店 + 按钮权限限制 |

> 实现：tea-framework 数据权限拦截器按"角色 + 当前用户绑定门店"自动拼接数据范围；顾客端数据天然按 tenant_id + store_id 过滤。

## 8. 附录：数据权限规则表（补充说明）

- 数据权限与菜单权限**叠加生效**：先有菜单/按钮权限，再按数据范围过滤数据。
- 顾客端不做 RBAC，全部按 `tenant_id + store_id` 硬过滤，且只能访问"营业中门店 + 可售商品"。
- 加盟商等级（A/B/C）一期为**人工评定**字段（F-FRA-01），用于分级价格表取价；二期支持按营业额自动评定。
- **平台管理员（R1）对租户业务数据仅只读审计（👁）**，不可操作（P0-3 决策）；仅平台自身功能（品牌/套餐/全局配置）可操作。
