## 关键决策 / 结论

- **自建可回收数据**替代依赖演示库状态：S8 建 smoke-r8（R8 店员，种子角色 id=8，跑完 PUT status=0 停用、重跑复用）；S6 建临时满减券模板（门槛按运行时单价动态算：`3件小计-(3件-1件)/2` 恒满足 1件<门槛≤3件，面值 min(50,门槛/2)，跑完 PUT status=2）
- **差值断言**贯穿：余额/积分/库存 SUM/对账计数/日结全部前后差值，不硬编码演示库状态（M15 旧脚本跑一次即废的教训）
- 冒烟脚本入库 `tools/smoke/`，Temp 里 M15/M17 一次性脚本保留不入库（README 已注）
- UI 登录双路径：验证码框出现留空（后端一期不校验）→ 失败 fallback API 登录 + localStorage 注入 `teasaas:token`/`teasaas:token-name`（守卫自动拉菜单注册动态路由，直连 `/store-term/st-*` 可行）

## 实现期踩的坑（写进了脚本注释与 HANDOFF §2.21）

- **ReorderVO 字段是 `salePrice`** 不是 price（首跑 FAIL 定位）
- **PayRefund 出参是 `orderId`**（雪花字符串比较须 String() 归一）不是 orderNo
- **"不存在订单"负例 id 须 < Long.MAX**：9300000000000000001（9.3e18）JSON 反序列化溢出 → 999999 系统繁忙；改 9100000000000000001（9.1e18）→ 正确 30101
- 演示库当前事实：**无 R8 账号、券模板全部 status=2**——负例/资产场景必须自建数据
- B 端请求头名=登录响应 `tokenName`（即 `Authorization`，裸 token），非固定 satoken；C 端 `Authorization: Bearer`
- Playwright chromium 需 npmmirror 镜像：`PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright`
- Pos.vue 实收金额组件预填=应收，UI 流直接确认即可（找零=0；找零断言由 API S1 承担）
