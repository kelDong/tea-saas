## 关键决策 / 结论

- **framework←system 依赖倒置用 SPI**：framework 不能依赖 system，门店解析定义 `WsStoreBindingResolver` 接口、system 提供实现、framework `ObjectProvider` 可空注入
- **推送挂 afterCommit**：事务内 publish 只注册 `TransactionSynchronization`，提交后真正推送——防前端先收到通知重查到旧状态；推送异常只记日志绝不影响主流程
- **浏览器 WS 鉴权走 query token**（`/ws/orders?token=`，WS API 无法自定义请求头）；握手 401/403 在浏览器表现为 **1006 断开**（不是 1008）——客户端按断线退避重连，靠"重连前重读 token"在登出后自然停止
- **取消/超时不推**：待支付单不在接单页任何 tab（拍板记录）；退款推 STATUS_CHANGED(7)
- **storeId 是雪花字符串**（冒烟实证 `"2099772853422260225"`）——前端比较必须 `String()` 归一；tenantId(9001)/status/time 是数值（SafeLongSerializer 只字符串化超 2^53 的 Long）
- **`Transaction` 类路径坑之外的另一坑**：`HandshakeInterceptor` 的请求/响应类型在 `org.springframework.http.server.*`（不是 `org.springframework.http.*`），编译期才暴露
- 旧后端进程占着 jar 文件会让 spring-boot repackage 报"Unable to rename"——先 taskkill 再打包
