# Owner Agent 定义

> 本文件定义 `.harness/` 的主人角色、职责边界与工作原则，供任何 AI 编码工具（vibe coding）在接手本项目时对齐。

## 1. 项目主人设定

| 项 | 内容 |
|---|---|
| 角色 | Owner / 主理人（产品负责人 + 技术负责人 + 运营） |
| 背景 | 个人全栈开发者，独自承接茶饮 SaaS 从立项到推广全流程 |
| 核心目标 | 最小闭环跑通 → 拿到种子品牌 → 复制推广 |
| 决策风格 | 偏好 MVP 思维、YAGNI、先跑通再打磨；重大变更先评审再动手 |

## 2. 工作原则（Owner 对 Agent 的期望）

1. **先文档后代码**：开发前必须确认需求（PRD）与设计（数据库/规范）已定稿，禁止在未评审的需求上写代码
2. **遵守红线**：任何产出不得违反 `rules/编码规范.md` 中的红线；违反即返工
3. **MVP 优先**：能砍的功能砍掉，把时间投在业务闭环（点单→支付→接单→报表）上
4. **可回滚**：每步改动走 Git 分支 + 提交规范，能回退
5. **诚实**：不清楚就问；做不了/有风险要提前说，不硬撑

## 3. 架构决策基线（已确认，不可擅自变更）

| 决策 | 结论 | 依据 |
|---|---|---|
| 架构 | 单项目 Maven 多模块（模块化单体），一期不上微服务 | 规划书 5.1 |
| 地基路线 | 自研 | 规划书 5.3 |
| 目标客户 | 茶饮连锁品牌总部（直营+加盟混合），租户=品牌 | 规划书 3.1 |
| 加盟商-门店 | 1:N（一个加盟商多家店） | 决策记录 |
| 库存驱动 | BOM 实时反算扣减（下单扣原料库存，不足自动禁售） | 规划书 6 |
| 支付回调 | 本地表 + 定时重试，一期**不引 MQ** | PRD F-PAY-01 |
| 退款 | 整单退 + 已核销券不退还 | PRD F-PAY-02 |
| 平台管理员 | 对租户业务数据只读审计 | PRD 权限矩阵 |
| 开发组织 | **分阶段并行**：M2 串行打地基 → M3 后端业务用 subagent fan-out（模块级原子任务）→ 后端接口可运行后按端并行前端（看板任务=独立会话，读 .harness 接上下文） | changes 记录 |

## 4. Agent 可执行范围 vs 需 Owner 确认的范围

| 类型 | 例 | 处理 |
|---|---|---|
| 直接执行 | 按 PRD/规范写代码、建表、补测试、修复 | 直接做，走规范 |
| 需确认 | 新增模块/功能、改数据库结构、引入新依赖、改技术栈 | 先出方案问 Owner |
| 禁止 | 违反红线、擅自改生命周期（切微服务）、动决策记录 | 禁止 |

## 5. 技术栈（已锁定）

- **后端**：JDK 21 + Spring Boot 3.5.5 + MyBatis-Plus 3.5.12 + MySQL 8.0 + Redis 7.x + Sa-Token 1.44
- **前端后台**：Vue 3 + Vite + Pinia + Element Plus（+ TypeScript）
- **小程序**：uni-app（Vue3 语法）
- **构建**：Maven 3.9+，Node 20 LTS+
