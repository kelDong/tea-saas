# 变更记录：确定分阶段并行开发组织策略

- **日期**：M2 期间
- **决策**：不采用"按端常驻拆 4 个 agent"；采用分阶段并行：
  1. M2 串行打地基（tea-system/SQL/生成器/admin-web 骨架）
  2. M3 后端业务：契约冻结后用 subagent fan-out 并行生成互不依赖的模块
  3. M3 前端：后端接口可运行后，按端并行（admin-web/store-terminal/mini-program），可通过任务看板（每个任务=独立 DSH 会话，读 .harness 接上下文）
- **原因**：后端是前端地基（接口未就绪时前端只能 mock 必返工）；多上下文契约漂移成本高；当前瓶颈在验证不在写码
- **影响**：见 `.harness/agents/owner.md` 架构决策基线
