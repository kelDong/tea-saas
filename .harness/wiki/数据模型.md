# 数据模型（数据库 Schema 与表定义）

> 核心表结构概览。权威定义见 `docs/茶饮SaaS-数据库设计.md`（v1.1，33 张表 + 3 张 v1.1 新增）。

## 通用约定

- 主键 `id BIGINT`（雪花）；所有业务表含 `tenant_id`、`del_flag`、审计字段
- 金额存"分"整数；原料数量 `DECIMAL(10,3)`
- 无物理外键；InnoDB + utf8mb4

| `sys_user_store` | 用户-门店绑定（一人多店） |

| 表 | 说明 |
|---|---|
| `inv_store_material_stock` | 门店原料库存（乐观锁 version，禁止负库存） |
| `inv_stock_log` | 库存变动流水（下单扣/超时回补/退款回补/采购入库/盘点） |

### 订单/支付（tea-order / tea-payment）
| 表 | 说明 |
|---|---|
| `ord_order` | 订单（order_source：1 小程序/2 门店收银；7 态状态机） |
| `ord_order_item` | 订单明细（携带 formula_id 快照用于扣库存） |

| `pay_callback_task` | 支付回调重试任务（本地表+定时，一期不引 MQ） |

### 会员/营销（tea-member / tea-marketing）
| 表 | 说明 |
|---|---|
| `mem_member(_level)` / `mem_points_log` / `mem_wallet` / `mem_recharge_record` | 会员/等级/积分/储值 |
| `mkt_coupon_template` / `mkt_coupon_scope` / `mkt_coupon` | 券模板/范围/用户券 |

### 报表（tea-report）
按订单流水聚合，不建表；二期可选 `daily_store_report` 快照表。

## 库存一致性（核心）

```sql
-- 下单扣减（条件 UPDATE 防超卖，影响行=0 则整单失败）
UPDATE inv_store_material_stock
   SET stock_qty = stock_qty - #{needQty}, version = version + 1
 WHERE tenant_id = #{tenantId} AND store_id = #{storeId}
   AND material_id = #{materialId} AND stock_qty >= #{needQty};
```

可售判定：商品按配方原料逐项检查库存充足（`NOT EXISTS` 缺料即不可售）。

## 建表顺序

`tenant/sys_package/sys_menu` → 角色/用户/加盟商 → BOM → 商品 → 门店 → 供应商/分级价/采购 → 库存 → 订单/支付/回调 → 会员 → 优惠券 → 操作日志

## 初始化数据

`sys_package`（三档）、`sys_menu`（含按钮权限码 `bom:add`/`purchase:ship`/`pos:create`）、`sys_role`（R1–R8）、`sys_user`（平台管理员+首个测试品牌）、`tenant`（演示品牌）
