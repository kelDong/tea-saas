# 业务模型与实体关系

> 项目的业务主线、领域模型、关键实体关系。设计/编码前先理解本页。

## 1. 业务主线（核心闭环）

```
总部产品研发：原料 → 配方BOM → 商品(产品库)
总部供应链：供应商 + 分级价格(原料×等级)
加盟商：从产品库上架 → 提交采购单 → 管理门店库存
顾客：小程序选门店 → 浏览可售商品(库存联动) → 下单支付 → 取餐
门店/店员：接单 → 制作 → 核销
总部：全局报表（经营 + 库存）
```

## 2. 组织与租户模型

```
平台管理员（超级租户）—— 品牌入驻/套餐/全局配置
   └── 品牌商（租户，隔离单位，tenant_id）
         ├── 总部（R2–R5：研发/供应链/运营/老板）
         ├── 加盟商（1:N 门店，等级 A/B/C 决定采购价）
         ├── 直营门店（挂总部，不挂加盟商）
         └── 顾客（会员，归属品牌，跨门店通用）
```

## 3. 核心实体关系

| 关系 | 说明 |
|---|---|
| 配方 ← 原料 | `bom_formula_item`：配方 N—M 原料（用量） |
| 商品 → 配方 | `prd_product.formula_id` 引用一个配方 |
| 门店 → 商品 | `prd_listing`：门店上架（本店售价，引用总部商品） |
| 门店 → 原料库存 | `inv_store_material_stock`（store × material） |
| 加盟商 → 门店 | `fra_store.franchisee_id`，1:N |
| 加盟商 → 采购 | `sup_purchase_order`：采购单状态机 |
| 顾客 → 订单 | `ord_order`（member_id，order_source 区分小程序/门店收银） |
| 订单 → 扣库存 | 按 `ord_order_item.formula_id` 快照反算原料扣减 |

## 4. 关键概念

- **商品可售** = 该门店所有配方原料 `stock_qty >= 配方用量`（实时判定，见数据模型）
- **分级价格** = `sup_tier_price`（原料 × 等级），采购单按等级取价
- **订单来源**：小程序（1）/ 门店收银（2），后者支持现金/微信收款码/储值
- **储值支付**：独立通道，一期不与微信混合支付

## 5. 角色与权限

8 个 B 端角色：R1 平台 / R2 总部管理 / R3 研发 / R4 供应链 / R5 运营 / R6 加盟商 / R7 店长 / R8 店员。
- 总部管理员 = R3+R4+R5 能力集
- 平台管理员对租户数据只读审计
- 数据权限：总部（全品牌）/ 加盟商（名下门店）/ 店长（本店）/ 店员（本店只读）

## 6. 状态机

| 领域 | 状态机 |
|---|---|
| 订单 | 待支付 → 已支付 → 制作中 → 待取餐 → 已完成；可取消/已退款 |
| 采购单 | 待确认 → 已确认 → 已发货 → 已入库；已取消 |
| 支付 | 待支付 → 成功 / 失败 / 已关闭 |
