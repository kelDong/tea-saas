# SKILL: 专家评审

> 目的：评审代码/PR/设计，重点是红线、多租户安全、业务一致性。产出评审结论（通过/驳回/需修改）。

## 评审维度

1. **红线违规**（一票否决，见 `rules/编码规范.md`）：
   - 金额非 Integer 分？Redis key 无前缀？未幂等？
   - BizException 缺失/异常外泄？@Autowired 字段注入？@Transactional 无 rollbackFor？
   - 响应非 Result<T>？
2. **多租户安全**（一票否决）：
   - 是否绕过租户插件？数据范围是否显式限定？越权校验（归属）是否做？
3. **业务一致性**：
   - 状态机流转是否只允许合法路径？金额计算（券+积分+储值）是否精确？
   - 是否与 PRD 功能编号一致？是否违反已定决策（只整单退款、不混合支付）？
4. **事务与并发**：
   - 写操作是否在原子事务内？库存扣减是否防超卖（条件 UPDATE）？超时回补？
5. **代码质量**：
   - 命名、分层、魔法值、日志、吞异常、性能（N+1、索引）

## 输出格式

```
评审结论：通过 / 驳回 / 需修改
- P0（阻断）：...
- P1（建议）：...
- 多租户隔离用例：通过/未覆盖
```

## 重点复核（本项目特有）

- [ ] 可售判定：`stock_qty >= Σ(配方用量)` 逻辑正确？
- [ ] 采购计价：是否按加盟商等级取分级价格快照？
- [ ] 门店收银订单：`order_source=2` 区分，是否计入日结？
