# SKILL: 单元测试编写

> 目的：为核心业务写出高覆盖、可信的单测。覆盖率要求：订单状态机/优惠券/金额/库存扣减 ≥ 90%。

## 测试分层

| 层 | 框架 | 位置 | 命名 |
|---|---|---|---|
| 单元测试 | JUnit5 + Mockito | 各模块 `src/test/java` | `OrderServiceTest` |
| 集成测试 | SpringBootTest + H2 | tea-server `src/test` | `OrderFlowIntegrationTest` |
| 接口测试 | MockMvc / Apifox | tea-server | `OrderApiTest` |
| 并发测试 | JMeter | `test/` | 下单并发、库存扣减 |

## 编写原则

1. **一个测试只验一个行为**，断言明确
2. 单元测试用 Mock，不连真实库；集成测试用独立测试库
3. 不写死时间，用相对时间（`now()`）
4. 金额测试必须验证精确值（分），不做近似比较
5. 覆盖正常路径 + 边界（零值、空集合、超上限）+ 异常路径

## 核心必测用例（本项目）

| 场景 | 断言 |
|---|---|
| 订单状态机 | 非法流转（已完成→接单）抛异常；合法流转通过 |
| 优惠券计算 | 满减/折扣与订单金额精确联动 |
| 金额计算 | 券+积分+储值组合，分毫精确（无浮点误差） |
| 库存扣减 | 下单调库存；条件 UPDATE 防超卖；不足整单失败 |
| 退款 | 整单退；券不退还；储值部分退储值账户；回补库存 |
| 支付回调 | 幂等：重复回调只处理一次 |
| 多租户隔离 | A 品牌 token 访问 B 数据 → 403/空 |

## 输出

每个核心方法至少 3 个用例（正常/边界/异常）+ 覆盖率报告。
