# 开发流程规范

> 本项目从需求到上线的标准流水线。每个阶段有明确进入/产出/门禁。

## 阶段流水线

```
需求分析 → 设计(数据库/接口) → 编码 → 单元测试 → 评审 → 集成/联调 → 部署验证
```

## 1. 需求分析

- 产出：PRD（功能需求 + 验收标准）+ 权限矩阵
- 门禁：需求评审通过（P0/P1 决策拍板），未评审需求不进入开发
- 参考：`skills/request-analysis/SKILL.md`、`wiki/业务模型.md`

## 2. 设计

- 产出：数据库 Schema（`sql/`）、接口协议（OpenAPI）、模块边界
- 门禁：数据库设计评审通过；多租户字段/索引评估通过
- 参考：`wiki/数据模型.md`、`wiki/接口协议.md`

## 3. 编码

- 产出：按红线/规范的代码 + 单元测试
- 门禁：无红线违反；核心逻辑单测通过
- 参考：`rules/编码规范.md`、`skills/coding-skill/SKILL.md`

## 4. 单元测试

- 产出：核心业务单测（订单状态机、优惠券、金额、库存扣减 ≥90%）
- 门禁：`mvn test` 全绿；`skills/unit-test-write/SKILL.md` 要求达成
- 参考：`skills/unit-test-write/SKILL.md`、`skills/unit-test-ci/SKILL.md`

## 5. 评审

- 产出：PR（含变更描述 + 测试情况 + 关联功能编号）
- 门禁：编译通过 + 单测通过 + 无规范/红线违规 + 多租户隔离用例通过
- 参考：`skills/expert-reviewer/SKILL.md`

## 6. 集成/联调

- 全链路：研发配方 → 上架 → 采购入库 → 点单扣库存 → 支付 → 接单 → 报表
- 门禁：A 品牌数据 B 品牌不可见；库存并发无超卖；支付回调幂等

## 7. 部署验证

- 产出：Docker 镜像 → 测试环境 → 冒烟测试
- 门禁：冒烟通过（点单→支付→接单→核销全流程）
- 参考：`skills/deploy-verify/SKILL.md`

## Git 流程

- 分支：`main`（生产）→ `dev`（集成）→ `release/` → `feature/F-XXX-名称`
- 提交信息：`<type>(<scope>): <subject>`，如 `feat(order): 实现订单状态机 F-ORD-02`
- type：`feat/fix/refactor/docs/test/chore/perf/style`
- 一条提交只做一件事，引用功能编号

## 提交前 Checklist

- [ ] 无绕过租户插件 SQL
- [ ] 写操作有事务 + 操作日志/流水
- [ ] 金额全为"分"整数
- [ ] 无魔法值、无 System.out、无吞异常
- [ ] 接口有 OpenAPI 注解、错误码已登记
- [ ] 单测通过、核心逻辑有覆盖
- [ ] 越权校验（归属检查）已做

## 变更追踪

- 每次实质性变更（模块/表/接口）在 `.harness/changes/` 记录一份，命名 `YYYY-MM-DD-<概述>.md`
