# 编码规范（含红线）

> 后端起规范为硬性要求。**红线违反即返工，不得合入。**

## 红线（不可违反）

1. **金额字段必须使用 `Integer`（分）表示** 一一 禁止使用 `Float`/`Double`/`BigDecimal` 表示金额
2. **Redis Key 前缀必须为 `teasaas:`** 一一 禁止使用无名或通用前缀
3. **回调/消费处理必须幂等** 一一 每个处理者都必须安全处理重复消息（支付回调、库存扣减、退款异步）
4. **异常处理必须使用 `BizException` 体系** 一一 禁止原始异常泄露到 API 层
5. **Controller 必须构造器注入** 一一 禁止使用 `@Autowired` 字段注入
6. **Service `@Transactional` 必须声明 `rollbackFor`** 一一 禁止异常时静默提交
7. **Vue3 必须使用 `<script setup>` 语法** 一一 禁止使用 Options API
8. **API 响应必须遵循统一格式 `{code, message, data}`** 一一 使用 `Result<T>`，禁止自定义零散响应

## 通用编码约定

- 禁止 `System.out.println` / `printStackTrace`，统一 SLF4J
- 禁止硬编码魔法值：状态/类型必须用枚举（`OrderStatus.PAID`）
- 金额全为"分"整数运算；主键雪花 ID（`BIGINT`）
- 逻辑删除 `del_flag`；审计字段 `create_by/update_by/create_time/update_time`
- 事务只放 Service 层；写操作多表必须 `@Transactional`
- 分页用分页插件，禁止内存分页；禁止 `SELECT *`
- 集合判空用 `CollectionUtils.isEmpty` / `StringUtils.hasText`
- 参数校验用 Bean Validation（`@NotNull/@Size/@Pattern`），不散落手写 if

## 多租户红线

- 新表必须含 `tenant_id`
- **禁止**绕过租户插件（`@InterceptorIgnore(tenantLine="true")`）；确需绕过必须注释原因 + code review
- Service 层必须显式追加数据权限（`store_id IN (...)`），禁止全量查询后内存过滤
- 跨租户隔离测试：A 租户 token 访问 B 租户数据 → 期望 403/空结果

## 命名

| 类型 | 规则 | 示例 |
|---|---|---|
| 类 | 大驼峰 | `OrderService` |
| 方法 | 小驼峰，动词开头 | `createOrder()` |
| 常量/枚举值 | 全大写下划线 | `ORDER_STATUS_PAID` |
| 表 | 小写下划线（模块前缀） | `ord_order` |
| 接口 URL | RESTful，名词复数 | `/api/v1/orders` |

## API 响应

```java
// 成功
Result.success(data)          // {code:0, message:"success", data:...}
// 失败
Result.error(ErrorCode.BIZ_ERROR)   // {code:xxx, message:"...", data:null}
```

错误码格式：`模块(2) + 场景(2) + 序号(2)`，如 `040201`（支付回调签名失败）。模块：00 通用 / 01 系统 / 02 产品 / 03 订单 / 04 支付 / 05 会员 / 06 供应链 / 07 库存 / 08 加盟 / 09 营销 / 10 报表。
