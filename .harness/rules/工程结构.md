# 工程结构规范

> 项目目录结构与模块边界约定。违反即返工。

## 1. 顶层结构

```
tea-saas/                    # Git 仓库根（含父 POM）
├── pom.xml                  # 父 POM：统一依赖版本/dependencyManagement
├── .gitignore
├── .editorconfig
├── docs/                    # 项目文档（规划/PRD/数据库/规范/AI harness）
├── sql/                     # 数据库脚本（init/upgrade/test）
├── tea-common/              # 工具、常量、统一返回/异常（零框架依赖）
├── tea-framework/           # 安全、MyBatis-Plus、Redis、租户拦截器
├── tea-system/              # 租户、用户、角色、菜单、权限（地基核心）
├── tea-franchise/           # 加盟商、等级评定、门店档案
├── tea-supply/              # 原料、供应商、采购单、分级价格
├── tea-bom/                 # 配方 BOM、原料用量
├── tea-product/             # 商品、分类、规格、产品库、加盟商上架
├── tea-inventory/           # 门店原料库存、BOM 反算扣减
├── tea-order/               # 订单、状态机、门店手工收银
├── tea-payment/             # 支付、退款、回调重试
├── tea-member/              # 会员、积分、储值
├── tea-marketing/           # 优惠券、活动
├── tea-report/              # 报表、看板
├── tea-job/                 # 定时任务（回调重试、超时取消、对账）
└── tea-server/              # 启动模块（聚合入口，不含业务代码）
```

## 2. 模块边界（红线）

- `tea-server` 只含启动类 + yml，禁止业务代码
- `tea-common` 禁止引入 Spring（纯工具/常量/枚举）
- `tea-framework` 只放框架级配置，禁止业务逻辑
- 业务模块只依赖 `common`、`framework` 及下游业务模块，**禁止反向依赖**

## 3. 模块依赖方向（防循环）

```
common → framework → system → { bom, franchise, supply } → { product, inventory }
    → { order, payment, member, marketing, report } → server
```

- 上层可依赖下层；禁止 A 依赖 B 且 B 依赖 A
- 用 Maven Enforcer 强制校验（`dependencyConvergence` + `banDuplicatePomDependencyVersions`）

## 4. 包结构（以 tea-order 为例）

```
com.teasaas.order
├── controller/    # 参数接收/校验/调用 service（无业务逻辑）
├── service/       # 业务逻辑 + 事务边界（接口 + impl）
├── mapper/        # MyBatis-Plus Mapper（复杂 SQL 用 XML）
├── entity/        # 数据库实体（DO）
├── dto/           # 入参对象
├── vo/            # 出参对象
├── convert/       # 对象转换
├── enums/         # 模块内枚举
└── constants/     # 模块内常量
```

- 跨模块引用：只引下层 `dto/vo/enums`，禁止引下层 `entity`
